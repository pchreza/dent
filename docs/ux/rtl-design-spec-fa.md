# قرارداد طراحی RTL و تجربهٔ کاربری فارسی

## 1. اصول بصری

Design System تولیدشده برای این محصول سبک **Accessible & Ethical** را پیشنهاد می‌کند: کنتراست بالا، متن بزرگ، Focus واضح، ناوبری صفحه‌کلیدی و رفتار کم‌حرکت. محصول سلامت است؛ آرام، دقیق، قابل اعتماد و روشن باشد و از گرادیان‌های نئونی، شلوغی بصری و انیمیشن‌های تزئینی دوری شود.

پالت پایهٔ محصول:

| توکن | مقدار | کاربرد |
|---|---|---|
| `--color-primary` | `#0891B2` | اقدام‌های اصلی و لینک‌های کلیدی |
| `--color-primary-strong` | `#164E63` | متن/مرز اصلی با کنتراست بالا |
| `--color-secondary` | `#22D3EE` | اطلاعات و عناصر مکمل |
| `--color-success` | `#059669` | موفقیت/تکمیل |
| `--color-background` | `#ECFEFF` | سطح پس‌زمینهٔ آرام |
| `--color-surface` | `#FFFFFF` | کارت و فرم |
| `--color-danger` | `#B42318` | خطا، حساسیت و عملیات پرخطر |
| `--color-warning` | `#B54708` | هشدار و نیازمند اقدام |
| `--color-text` | `#0F172A` | متن اصلی |
| `--color-muted` | `#475569` | متن کمکی؛ نه برای متن اصلی |

مدیر کلینیک مجاز به تغییر رنگ‌های برند است، اما سیستم باید کنتراست حداقل 4.5:1 برای متن عادی و Focus قابل مشاهده را حفظ کند. رنگ تنها شاخص وضعیت نیست؛ Badge باید متن و/یا آیکون معنادار نیز داشته باشد.

## 2. فونت و متن

Vazirmatn به‌صورت local و با `@font-face` در وزن‌های لازم بسته‌بندی می‌شود. متن بدنه حداقل ۱۶ پیکسل در موبایل و line-height حدود ۱.۵ تا ۱.۷۵ دارد. ارتفاع ثابت برای متن فارسی ممنوع است. برچسب‌ها، خطاها، عنوان دکمه‌ها و متن‌های طولانی باید با دادهٔ واقعی فارسی تست شوند.

مقادیر فنی مانند موبایل، کد ملی، شماره فاکتور، URL، ایمیل، کد پرونده و کد پیگیری داخل `dir="ltr"` یا `<bdi>` ایزوله می‌شوند. متن کاربر با `dir="auto"` نمایش داده می‌شود. عدد، تاریخ و مبلغ در کامپوننت‌های مستقل Format می‌شوند.

## 3. ماتریس جهت

| عنصر | رفتار RTL |
|---|---|
| سند و Layout | `lang="fa" dir="rtl"` در ریشه؛ CSS منطقی و نه left/right. |
| ناوبری اصلی | در لبهٔ راست؛ ترتیب DOM نیز همان ترتیب معنایی باشد. |
| دکمهٔ بازگشت/جلو | آیکون بر اساس معنا Mirror شود؛ Accessible Label «بازگشت» باشد نه «فلش چپ». |
| ایمیل/URL/کد/موبایل | LTR و ایزوله؛ از برعکس‌کردن رشته خودداری شود. |
| جدول | عنوان و متن فارسی از راست؛ اعداد/کدها طبق نوع داده. |
| تایم‌لاین درمان | قابل تنظیم و با متن مرحله؛ نباید صرفاً با معکوس‌کردن نمودار تصمیم‌گیری شود. |
| تقویم | هفته و روز مطابق تقویم شمسی و قرارداد محصول؛ ساعت‌ها با جهت و خوانایی محلی. |
| نمودارها | محور و legend بر اساس معنا؛ رنگ تنها شاخص نباشد؛ جدول جایگزین وجود داشته باشد. |
| لوگو و تصویر | Mirror نشود، مگر دارایی صریحاً جهت‌دار و تاییدشده باشد. |
| اعلان | آیکون و action در trailing/inline-end؛ ترتیب خواندن DOM حفظ شود. |

## 4. Layout و Responsive

Breakpoints پذیرش: ۳۷۵، ۷۶۸، ۱۰۲۴ و ۱۴۴۰ پیکسل. کارکنان عمدتاً دسکتاپ/تبلت و بیمار عمدتاً موبایل است. صفحهٔ بیمار باید بدون جدول عریض قابل استفاده باشد؛ جدول‌های کارکنان در موبایل به کارت یا اسکرول کنترل‌شده با عنوان ثابت تبدیل می‌شوند.

از `margin-inline`, `padding-inline`, `inset-inline`, `border-inline` و `text-align: start/end` استفاده می‌شود. `left/right` فقط برای موارد فیزیکی یا استثنای مستند مجاز است. Touch Target حداقل ۴۴×۴۴ پیکسل، Focus Ring سه تا چهار پیکسل و فاصلهٔ کافی برای خطاهای فرم الزامی است.

## 6. فرم‌ها و خطاها

هر ورودی label واقعی، hint کوتاه، وضعیت required، خطای نزدیک فیلد و پیام موفقیت واضح دارد. دکمه در عملیات async غیرفعال و حالت loading دارد. خطاهای سرور به زبان فارسی و بدون جزئیات فنی نمایش داده می‌شوند؛ کد پیگیری قابل کپی است. در فرم‌های طولانی، بخش‌بندی، خلاصهٔ خطا و حفظ دادهٔ معتبر کاربر الزامی است.

## 7. دسترس‌پذیری

- Skip link برای محتوای اصلی.
- Tab order مطابق جریان کار و ترتیب DOM.
- نام دسترس‌پذیر برای icon-only button.
- عدم استفاده از emoji به‌عنوان آیکون؛ SVG یکنواخت.
- پشتیبانی از `prefers-reduced-motion`.
- کنتراست متن و Focus قابل مشاهده.
- alt text برای تصاویر معنادار و alt خالی برای تصاویر تزئینی.
- جدول گزارش علاوه بر نمودار ارائه می‌شود.
- اعلان‌های مهم با `aria-live` مناسب و بدون ایجاد حلقهٔ صوتی.

## 8. فهرست بررسی RTL پیش از هر گیت

1. متن فارسی واقعی، طولانی، کوتاه، خطا و مقدار خالی.
2. ترکیب فارسی/لاتین در کد، ایمیل، موبایل، URL و نام دارو.
3. عدد فارسی/لاتین، تومان، جداکنندهٔ هزارگان و تاریخ شمسی.
4. فرم در موبایل ۳۷۵ پیکسل بدون overflow.
5. ناوبری، مودال، dropdown، tooltip، toast و جدول.
6. کیبورد، Focus، Screen Reader و Zoom.
7. Reduced Motion و Loading/Skeleton.
8. نمودار دندان، تقویم، تایم‌لاین درمان و نمودار گزارش.
9. چاپ رسید حرارتی و A4 با جهت صحیح.
10. مقایسهٔ LTR فنی برای تشخیص وابستگی ناخواسته به معکوس‌سازی.
