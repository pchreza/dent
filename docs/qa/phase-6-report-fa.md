# گزارش QA فاز پروندهٔ دندان‌پزشکی پیشرفته

**تاریخ اجرا:** ۱۲ اوت ۲۰۲۶
**مخزن:** `pchreza/dent`
**دامنه:** Custom Fields، نمودار دندان FDI، تاریخچهٔ رویدادهای بالینی و طرح درمان آیتم‌محور

## جمع‌بندی

این فاز با حفظ سازگاری داده‌های قبلی پیاده‌سازی شد. ستون JSON قدیمی `patients.custom_fields` حذف یا بازنویسی نشده است و فیلدهای جدید در مدل ساخت‌یافتهٔ Tenant-scoped ذخیره می‌شوند. نمودار دندان از الگوی append-only استفاده می‌کند؛ تغییر وضعیت یک دندان رویداد تازه می‌سازد و هیچ مسیر حذف یا ویرایش فیزیکی برای سابقه ارائه نمی‌شود.

طرح درمان اکنون می‌تواند چند آیتم داشته باشد. هر آیتم به مرحلهٔ درمان، خدمت کاتالوگ اختیاری، کد دندان، سطح، وضعیت، اولویت، هزینهٔ برآوردی، تاریخ برنامه‌ریزی و یادداشت متصل می‌شود. تغییر وضعیت آیتم در تراکنش مستقل ثبت شده و تاریخچهٔ قبل/بعد و دلیل را نگه می‌دارد.

## قابلیت‌های تحویل‌شده

| بخش | خروجی |
|---|---|
| فیلدهای سفارشی | تعریف Tenant-scoped، نوع‌های متن کوتاه/بلند، عدد، تاریخ، بله/خیر و فهرست، ترتیب، الزامی/فعال و نگهداری مقدار بیمار |
| نمودار دندان | کدهای FDI دندان دائمی و شیری، سطح‌های `O/M/D/B/L/I`، وضعیت‌های بالینی، کارت انتخاب دندان و تاریخچهٔ غیرقابل‌حذف |
| طرح درمان | چند آیتم، مرحله، خدمت، دندان/سطح، اولویت، وضعیت، هزینه و تاریخ برنامه‌ریزی |
| ممیزی | ثبت رویداد برای تعریف فیلد، مقدار پرونده، نمودار و طرح درمان؛ تاریخچهٔ تغییر وضعیت آیتم |
| مجوزها | استفاده از `clinical.*`، `dentistry.*` و `treatments.*` موجود؛ منشی اجازهٔ تغییر نمودار و آیتم درمان را ندارد |
| RTL و دسترس‌پذیری | `dir=rtl`، فونت Vazirmatn، labelهای فرم، focus قابل مشاهده، کدهای FDI و مبلغ با جداسازی LTR و responsive layout |

## سناریوهای پذیرش

سناریوی مدیر کلینیک برای ایجاد یک فیلد انتخابی و ذخیرهٔ مقدار آن روی پرونده موفق بود. ثبت دو رویداد متوالی برای یک دندان، بدون حذف رویداد قبلی، موفق بود و تلاش برای مشاهدهٔ بیمار Tenant دیگر با `404` مسدود شد. تغییر وضعیت آیتم درمان از `planned` به `in_progress` تاریخچهٔ وضعیت را ایجاد کرد. تلاش منشی برای ثبت نمودار دندان با `403` رد شد.

## موارد خارج از محدوده

فایل‌های پزشکی و دانلود authorization‌شده، نسخه‌نویسی، نمودار SVG گرافیکی، SMS/IPPanel، Email واقعی، درگاه پرداخت، پورتال کامل بیمار و گزارش‌ساز در فازهای بعدی باقی می‌مانند. هشدار غیرمسدودکنندهٔ Vite دربارهٔ resolve نشدن فونت در زمان build همچنان وجود دارد؛ فایل فونت در `public/fonts` قرار دارد و باید در Smoke Test واقعی HTTPS/cPanel کنترل شود.

## دستور آزمایش محلی

```bash
php artisan migrate:fresh --seed --force
php artisan optimize:clear
php artisan view:cache
php artisan test
vendor/bin/pint --test
composer validate --strict
composer audit
pnpm run build
```

این گزارش تا زمان ثبت Commit و Release تمیز، وضعیت QA فاز را ثبت می‌کند و پس از انتشار باید شمارهٔ Commit نهایی به آن افزوده شود.
