# سیستم طراحی رابط Dent — فارسی RTL، الهام‌گرفته از Conca

## 1. هدف

این سند مرجع اجرایی بازطراحی رابط Dent است. هدف، ایجاد داشبوردی روشن، متراکم، قابل‌اسکن و حرفه‌ای برای مدیریت کلینیک دندان‌پزشکی است. ساختار بصری از الگوی پنل‌های مدیریتی مدرن الهام می‌گیرد، اما تمام اجزا، کد و دارایی‌های Dent مستقل و اختصاصی هستند.

## 2. اصول تجربه

| اصل | تصمیم اجرایی |
| --- | --- |
| وضوح بالینی | هشدار حساسیت، وضعیت درمان، موعد نوبت و بدهی همیشه پیش از جزئیات ثانویه دیده شوند. |
| تراکم کنترل‌شده | دادهٔ مدیریتی در کارت‌ها و جدول‌ها جمع‌وجور است، اما متن فارسی با ارتفاع خط کافی و بدون برش نمایش می‌یابد. |
| اقدام در متن | عملیات اصلی هر صفحه در header و عملیات ردیف در انتهای منطقی هر ردیف قرار می‌گیرند. |
| صداقت داده | فقط دادهٔ واقعی نمایش داده می‌شود؛ برای نبود داده empty state مفید نمایش داده خواهد شد. |
| پیشرفت تدریجی | جزئیات سنگین در `details`، کارت‌های ثانویه یا صفحهٔ اختصاصی قرار می‌گیرند، نه در صفحهٔ اصلی. |

## 3. جهت، زبان و متن دوسویه

ریشهٔ HTML همواره `lang="fa"` و `dir="rtl"` دارد. متن فارسی راست‌چین است، اما داده‌های دارای قرارداد LTR با `bdi` یا `dir="ltr"` ایزوله می‌شوند.

| داده | رفتار لازم |
| --- | --- |
| شماره موبایل، کد ملی، FDI، شناسه، مبلغ، درصد، ساعت | `dir="ltr"` و `bdi` |
| نام فارسی، عنوان خدمت، یادداشت بالینی | جهت موروثی RTL |
| URL و ایمیل | `dir="ltr"` و اجازهٔ wrap منطقی |
| تاریخ شمسی | متن فارسی؛ بخش عددی در صورت نیاز با `bdi` |
| متن تولیدشده توسط کاربر | `bdi dir="auto"` در محل نمایش عمومی |

تمام فاصله‌ها و مرزها با ویژگی‌های منطقی CSS مانند `padding-inline`، `border-inline-start` و `inset-inline-end` نوشته می‌شوند. هیچ API یا class مشترکی با نام `left` و `right` تعریف نمی‌شود.

رنگ به‌تنهایی حامل وضعیت نیست؛ status badge و هشدار همواره برچسب متنی و در موارد بحرانی icon دسترس‌پذیر خواهند داشت.

### تایپوگرافی و فاصله

فونت اولویت‌دار `Vazirmatn` آفلاین است. بدنه روی 16px با `line-height: 1.75` تنظیم می‌شود. عنوان صفحه در desktop برابر 28px و در mobile برابر 24px است. عنوان بخش 18px، متن label برابر 14px و متن راهنما حداقل 12px خواهد بود.

مقیاس فاصله‌گذاری از 4، 8، 12، 16، 20، 24، 32 و 40 پیکسل استفاده می‌کند. ارتفاع هدف لمس دکمه‌ها و کنترل‌ها حداقل 44px است. شعاع سطوح بین 10 و 16px و سایه‌ها کوتاه و کم‌رنگ هستند.

## 5. Shell و ناوبری

### دسکتاپ

پوسته شامل header چسبان در بالا، sidebar ثابت در راست و canvas اصلی است. Header شامل دکمهٔ منو در viewportهای کوچک، breadcrumb، context کلینیک، میانبر «اقدام سریع» فقط در صورت وجود مسیر معتبر، اعلان‌ها و منوی کاربر است. Sidebar با گروه‌های زیر نمایش داده می‌شود و هر گروه بر مبنای مجوزها فیلتر می‌شود:

1. **نمای کلی:** داشبورد.
2. **مراجعان و درمان:** بیماران، وضعیت دندان‌ها در داخل پرونده، فیلدهای پرونده، مراحل درمان.
3. **برنامه‌ریزی:** تقویم نوبت‌ها و ثبت نوبت.
4. **مالی:** فاکتورها.
5. **مدیریت:** شعبه‌ها، کاربران، درخواست‌های QR، اعلان‌ها.
6. **سامانه:** کلینیک‌ها و تنظیمات ظاهر، تنها برای سوپرادمین.

مسیر فعال با route جاری مشخص می‌شود و هرگز به‌صورت ثابت روی داشبورد نمی‌ماند.

### موبایل

در کمتر از 1024px، sidebar در یک dialog/drawer با backdrop قرار می‌گیرد. بازکردن Drawer focus را به آن منتقل می‌کند، کلید Escape آن را می‌بندد و Tab در محدودهٔ آن باقی می‌ماند. پس از بسته‌شدن، focus به دکمهٔ منو بازمی‌گردد. ناوبری افقی اسکرول‌شونده استفاده نخواهد شد.

## 6. الگوی اجزا

| جزء | قواعد اصلی |
| --- | --- |
| Page header | breadcrumb یا eyebrow، عنوان، توضیح کوتاه، سپس action cluster؛ در mobile عمودی می‌شود. |
| Card | سطح سفید با مرز یک‌پیکسلی قابل‌دیدن، padding 20–24px و title/action منطقی. |
| Button | primary، secondary، ghost و danger؛ آیکون در inline-start یا inline-end مطابق معنا؛ focus و disabled صریح. |
| Icon button | فقط با `aria-label`، حداقل 44×44px، tooltip در desktop. |
| Status badge | متن صریح به همراه رنگ؛ برای حالت بحرانی icon و شرح قابل‌فهم. |
| Table | header روشن، ردیف hover، عملیات در inline-end، wrapper افقی کنترل‌شده؛ در mobile با `data-label` یا چیدمان card. |
| Form field | label، نشانهٔ الزام، hint و خطا به‌هم متصل؛ error در نزدیکی input؛ کنترل‌ها حداقل 44px. |
| Empty state | عنوان، توضیح کاربردی و فقط در صورت مجازبودن CTA واقعی. |
| Alert | نقش ARIA مناسب، رنگ، متن و در صورت ضرورت دکمهٔ dismiss. |

## 7. آیکون‌ها و حرکت

آیکون‌ها SVG inline از یک set یکپارچه هستند و نام دسترس‌پذیر دارند. آیکون‌های ناوبری و بازگشت مطابق معنای فضایی در RTL mirror می‌شوند؛ آیکون ساعت، refresh، نمودار، لوگو و دادهٔ عددی mirror نمی‌شوند.

حرکت‌ها به fade و transform با مدت 150 تا 220 میلی‌ثانیه محدود می‌شوند. برای `prefers-reduced-motion` تمام transition و animation غیرضروری حذف می‌شود. هیچ animation دائمی برای عناصر عملیاتی استفاده نمی‌شود.

## 8. الگوهای دامنه‌ای

### پروندهٔ بیمار

هدر بیمار شامل نام، شماره پرونده، وضعیت، تاریخ به‌روزرسانی و اقدامات واقعی است. هشدار حساسیت بحرانی در بالا و مستقل از رنگ نمایش داده می‌شود. خلاصهٔ هویتی، فیلدهای بالینی، طرح درمان، حساسیت، دارو، سوابق و یادداشت‌ها با کارت‌های قابل‌اسکن و عنوان‌های روشن ارائه می‌شوند.

### وضعیت دندان‌ها

صفحهٔ مینیمال نسخهٔ 0.4.0 حفظ می‌شود. فهرست آخرین وضعیت دندان، فرم ثبت سریع و تاریخچهٔ کامل باقی می‌مانند؛ تنها کارت‌ها، chipها، header، inputها و responsive layout با این Design System یکپارچه می‌شوند. نقشهٔ فک، SVG و timeline به صفحه بازنمی‌گردند.

### تقویم و فاکتور

تقویم هفتگی شمسی روز جاری، وضعیت نوبت و ساعت را با خوانایی بالا نمایش می‌دهد. در مالی، مبلغ‌ها LTR ایزوله می‌شوند، وضعیت‌های فاکتور label متنی دارند و عملیات تنها از مسیرهای فعلی انجام می‌شود.

## 9. معیار پذیرش طراحی

رابط زمانی آمادهٔ انتشار است که همهٔ صفحه‌ها در 375، 768، 1024 و 1440 پیکسل بدون scroll افقی ناخواسته قابل‌استفاده باشند؛ همهٔ مسیرهای موجود حفظ شوند؛ keyboard order با ترتیب بصری هم‌راستا باشد؛ تمام فرم‌ها label و error داشته باشند؛ رنگ متن معمولی نسبت کنتراست حداقل 4.5:1 داشته باشد؛ و Vazirmatn آفلاین در همهٔ جریان‌ها بارگذاری شود.
