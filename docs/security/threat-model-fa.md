# مدل تهدید و کنترل‌های امنیتی — نسخهٔ MVP

## 1. دارایی‌های حساس

| دارایی | اثر افشا/تغییر | سطح |
|---|---|---:|
| پرونده و سوابق پزشکی بیمار | نقض محرمانگی و آسیب حرفه‌ای/حقوقی | بحرانی |
| کد ملی و موبایل | سرقت هویت و ورود غیرمجاز | بحرانی |
| حساسیت و دارو | خطر مستقیم برای درمان | بحرانی |
| فاکتور، پرداخت و کیف پول | زیان مالی و اختلاف حساب | بحرانی |
| کلید رمزنگاری و `.env` | دسترسی کامل به سامانه | بحرانی |
| لاگ ممیزی | از بین رفتن قابلیت پیگیری | شدید |
| فایل‌های تصویری | افشای دادهٔ درمانی | شدید |
| اطلاعات پلن و مصرف | اختلال تجاری | متوسط |

## 2. مرزهای اعتماد

```text
مرورگر بیمار/کارمند
   -- HTTPS + CSRF + Session --> برنامهٔ PHP
برنامهٔ PHP
   -- Tenant Context + Policy --> MySQL
برنامهٔ PHP
   -- signed/private path --> Storage فایل
Cron cPanel
   -- application key + lock --> Jobs زمان‌دار
سوپرادمین
   -- Support Access + reason + audit --> Tenant
``` 

کلاینت غیرقابل اعتماد است. مقدار `tenant_id` از فرم یا URL نباید مبنای اعتماد باشد. Cron نیز باید مانند درخواست کاربر، نتیجهٔ کار و خطا را ثبت کند و از اجرای هم‌زمان کارهای تکراری جلوگیری نماید.

## 3. تهدیدها و راهکارها

| تهدید | سناریو | کنترل اجباری |
|---|---|---|
| Cross-Tenant Data Access | کاربر Tenant A شناسهٔ بیمار Tenant B را در URL می‌گذارد. | Tenant Context سمت سرور، Global Scope/Repository، Policy و تست منفی برای همهٔ مسیرها. |
| IDOR | تغییر شناسهٔ فاکتور/فایل/اعلان. | Authorize بعد از resolve کردن رکورد در Tenant فعال؛ عدم استفاده از `Model::find()` خام در کنترلر. |
| Brute Force | تلاش پیاپی برای ورود با کد ملی. | Rate limit، backoff، قفل موقت، ثبت تلاش و پیام عمومی بدون افشای وجود کاربر. |
| CSRF | ارسال فرم تغییر اطلاعات از سایت خارجی. | CSRF توکن، SameSite Cookie و بررسی Origin در عملیات حساس. |
| XSS | ثبت یادداشت شامل HTML/Script. | Escape در View، پاک‌سازی HTML مجاز، عدم `unescaped output` برای متن کاربر. |
| SQL Injection | فیلتر جست‌وجو با Query خام ناامن. | Query Builder/Binding، اعتبارسنجی و whitelist مرتب‌سازی. |
| File Upload | فایل مخرب یا مسیر traversal. | MIME واقعی، پسوند مجاز، سقف حجم، نام تصادفی، ذخیرهٔ خارج از public و پاسخ از Controller مجاز. |
| Privilege Escalation | منشی با تغییر payload مجوز مدیر می‌گیرد. | عدم mass assignment حساس، Form Request، Policy و تست نقش. |
| Support Abuse | سوپرادمین بدون دلیل وارد Tenant می‌شود. | Support Session زمان‌دار، دلیل اجباری، نوار هشدار و Audit کامل. |
| Data Export Leakage | خروجی شامل بیماران خارج از مجوز است. | Export Query مشترک با Tenant/Permission، لاگ درخواست و درج کاربر/زمان. |
| Session Theft | سرقت Cookie از دستگاه کارمند. | Secure/HttpOnly/SameSite، rotation بعد از ورود، خروج از همهٔ نشست‌ها و انقضا. |
| Secret Exposure | کلید IPPanel یا APP_KEY در مخزن. | `.env` خارج از Git، نمونهٔ بدون مقدار، بررسی Secret Scan و عدم درج کلید در Log. |
| Replay/duplicate job | اجرای دوبارهٔ اعلان یا کسر دوبرابر کیف پول. | idempotency key، unique reference، قفل دیتابیس و تراکنش. |
| Audit Tampering | مدیر لاگ تغییرات را حذف می‌کند. | مسیر حذف فقط سوپرادمین، لاگ حذف خود لاگ و سیاست نگهداری. |
| Error Leakage | Stack trace برای بیمار نمایش داده می‌شود. | صفحهٔ خطای فارسی + کد پیگیری؛ جزئیات فقط Log و پنل فنی. |

## 4. قواعد رمز و نشست

- رمز کارکنان و مدیران حداقل ۱۰ کاراکتر و تغییر رمز اولیه اجباری.
- رمز با الگوریتم پیش‌فرض امن Framework هش می‌شود؛ هرگز به‌صورت خام ذخیره یا Log نمی‌شود.
- پس از ورود موفق، Session ID چرخانده می‌شود.
- Cookieها `Secure`, `HttpOnly`, `SameSite=Lax/Strict` متناسب با نیاز هستند.
- عملیات حساس مانند تغییر مجوز، پرداخت، ابطال، حذف دائمی و ورود پشتیبانی نیازمند تأیید مجدد یا محدودیت نرخ هستند.
- پیام ورود ناموفق نباید مشخص کند شمارهٔ موبایل یا حساب وجود دارد.

## 5. کنترل فایل پزشکی

فایل تصویر تا سقف ۱ مگابایت و با پسوند JPG/PNG پذیرفته می‌شود. محتوای فایل با MIME واقعی بررسی می‌شود، نام فایل از کاربر پذیرفته نمی‌شود، متادیتای حساس در صورت نیاز پاک‌سازی می‌شود و مسیر Storage شامل شناسهٔ تصادفی است. دانلود با بررسی Tenant، بیمار، نوع فایل و مجوز انجام می‌شود.

## 6. تست‌های امنیتی اجباری

1. ورود و خروج نقش‌های پنج‌گانه.
2. تلاش برای دسترسی به IDهای Tenant دیگر با URL، فرم، Query و خروجی.
3. دورزدن مجوز با HTTP مستقیم بدون UI.
4. Brute Force و شمارش نرخ.
5. CSRF روی فرم‌های تغییر.
6. XSS در نام، یادداشت، پیام، دلیل و فیلتر.
7. SQL Injection در جست‌وجو و مرتب‌سازی.
8. Upload فایل غیرمجاز، فایل بزرگ، MIME جعلی و نام traversal.
9. مشاهدهٔ اعلان/فایل/پرونده خارج از محدوده.
10. ورود پشتیبانی بدون دلیل یا بعد از انقضای Support Session.
11. خروجی با فیلتر محدود و کنترل دادهٔ خروجی.
12. عدم وجود Secret در Git، ZIP، Log و گزارش خطا.

## 7. استاندارد گزارش رخداد

هر رخداد امنیتی باید شامل زمان، Tenant، کاربر، IP، User-Agent، مسیر، عملیات، رکورد، نتیجه و کد پیگیری باشد. کاربر فقط پیام فارسی ساده دریافت می‌کند. سوپرادمین پنل فنی برای فیلتر رخداد، شدت، کد پیگیری، وضعیت بررسی و پاسخ داخلی خواهد داشت.
