# راهنمای عملیاتی cPanel — قرارداد فاز صفر

## 1. پیش‌نیاز هدف

- PHP 8.2 یا 8.3.
- MySQL 8.0 یا سازگار با Migrationهای پروژه.
- افزونه‌های PHP موردنیاز پروژه، از جمله PDO MySQL، Mbstring، OpenSSL، XML، Ctype، JSON، Fileinfo، Tokenizer و Curl.
- دامنه یا زیردامنه با SSL فعال؛ تمام ترافیک عملیاتی باید HTTPS باشد.
- حداقل دسترسی ساخت دیتابیس و کاربر MySQL، ایجاد Cron Job و تنظیم Document Root.
- فضای کافی برای `vendor/`، فایل‌های کلینیک، بکاپ و Log.

## 2. ساختار انتشار

```text
release.zip
├── app/
├── bootstrap/
├── config/
├── database/
├── public/
├── resources/
├── routes/
├── storage/
├── vendor/
├── .env.example
├── artisan
├── composer.json
├── composer.lock
├── CHANGELOG.md
└── INSTALL.md
```

`public/` باید Document Root باشد. `.env` واقعی، فایل‌های بکاپ، Log و فایل‌های پزشکی نباید در Git یا ZIP عمومی قرار بگیرند.

## 3. مراحل نصب

1. ایجاد Database و User در cPanel.
2. Upload و Extract بستهٔ انتشار.
3. تنظیم Document Root روی `public` یا استفاده از مسیر امن معادل.
4. بازکردن `/install` و پذیرش شرایط.
5. بررسی نسخهٔ PHP و افزونه‌ها، پوشه‌ها و حافظه.
6. ورود اطلاعات MySQL و تست اتصال.
7. تنظیم نام محصول، برند، منطقهٔ زمانی، لوگو و کاربر سوپرادمین.
8. اجرای Migration و Seed در تراکنش‌های قابل کنترل.
9. ثبت APP_KEY و تنظیم Storage.
10. قفل نصب و تست ورود.
11. نمایش دستور Cron و لینک Health Check.

در صورت خطا، ویزارد باید مرحله، پیام فارسی ساده، کد پیگیری و Log امن ارائه کند و از ایجاد نصب نیمه‌کارهٔ غیرقابل بازیابی جلوگیری نماید.

## 4. Cron Jobهای پایه

نمونهٔ مفهومی؛ دستور نهایی پس از ساخت پروژه و مسیر cPanel تنظیم می‌شود:

```cron
* * * * * cd /home/USER/app && php artisan schedule:run >> /dev/null 2>&1
```

Jobهای زمان‌بندی‌شده:

| Job | تناوب پیشنهادی | رفتار تکرار |
|---|---|---|
| یادآوری نوبت | هر ۵ دقیقه | کلید یکتا بر اساس نوبت/رویداد/کانال. |
| بررسی اقساط | روزانه | فقط اقساط سررسیدشده و ثبت‌شده. |
| پاک‌سازی فایل موقت | روزانه | فقط فایل منقضی و ممیزی‌شده. |
| بکاپ کلینیک | روزانه/هفتگی طبق پلن | Lock، checksum و ثبت وضعیت. |
| حذف/آرشیو اعلان منقضی | روزانه | آرشیو، نه حذف بی‌ردپا. |
| سلامت سیستم | هر ۱۵ دقیقه | ثبت آخرین اجرا و هشدار پنل. |

## 5. ارتقا

1. نمایش نسخهٔ فعلی و نسخهٔ هدف.
2. قفل حالت تعمیرات.
3. گرفتن بکاپ کامل دیتابیس، فایل‌ها، تنظیمات و نسخهٔ فعلی.
4. اعتبارسنجی checksum بستهٔ ارتقا.
5. جایگزینی فایل‌ها به‌صورت اتمیک تا حد امکانات cPanel.
6. اجرای Migrationهای نسخه‌دار.
7. اجرای Smoke Test.
8. خارج‌کردن از حالت تعمیرات.
9. ثبت نسخه، زمان، کاربر، نتیجه و checksum.

اگر Migration شکست خورد، سیستم باید عملیات را متوقف کند، پیام کنترل‌شده نمایش دهد، امکان بازیابی بکاپ را فعال کند و لاگ کامل خطا را برای سوپرادمین ثبت نماید. ادامهٔ کورکورانهٔ Migration مجاز نیست.

## 6. بکاپ و بازیابی

بکاپ شامل دیتابیس Tenant یا کل سیستم، فایل‌های مرتبط، تنظیمات برند، Seedهای سفارشی، گزارش‌های ذخیره‌شده و اطلاعات لازم برای بازسازی است. هر بکاپ checksum، اندازه، زمان، نوع، وضعیت و تاریخ انقضا دارد.

بازیابی باید در مسیر امن و با تأیید قطعی انجام شود. برای بازگردانی کل سیستم، حالت تعمیرات و قفل ورود لازم است. بازگردانی یک کلینیک نباید دادهٔ کلینیک‌های دیگر را تغییر دهد؛ پیش از اجرا، دامنهٔ بازگردانی و مقصد باید در UI واضح باشد.
